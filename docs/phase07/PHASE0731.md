# Phase 07.3.1 — 現行毒システムの監査・共通化設計

## 目的・スコープ
- 目的: 現行単一毒・遺伝的耐性の挙動を変えずに実装位置、データの所有者、計算順序、診断指標を固定し、種をまたぐ共通毒システムの設計と受け入れ条件を確定する。
- 対象: Rust sim-coreの毒処理、設定、診断、Web標準毒設定、後方互換性、回帰検証の準備。
- 対象外: 共通毒処理の実装、複数毒、有毒/無毒の個体差、動物の毒生成、色学習、擬態の直接実装。07.3.1ではRust生態モデルを変更しない。

## 現行の毒計算式（正確な処理順序）
1. 摂食時、毒ONかつ摂食量 `eaten > 0` なら `dose = eaten * dose_per_nutrient`、`toxin_load += dose`。
2. 毒ON時、`toxin_load *= 1 - clearance_fraction_per_tick`。
3. `excess = max(toxin_load - damage_threshold, 0)`、`raw_damage = excess * hp_damage_per_excess_unit`。
4. `protection = clamp(toxin_resistance * resistance_effectiveness, 0, 1)`（耐性OFFなら0）。
5. `damage = f32(min(raw_damage * (1 - protection), f32::MAX))`、`hp -= damage`。
6. 耐性ONなら `cost = min(resistance_energy_cost_per_tick * toxin_resistance, reserve_energy)` を熱へ散逸。毒ON/OFFとは独立。
7. 植物は毒ON時に各個体のreserveから `min(plant_energy_cost_per_tick, reserve_energy)` を熱へ散逸。

毒量は無次元の状態値であり、栄養N/エネルギーの保存台帳へ新規資源として追加しない。将来、毒の生成に使うエネルギー・栄養コストは台帳で処理する。

## 共通化の設計（07.3.2以降、まだ未実装）
- `ToxinTypeId`: 毒の種類の識別子。まずは単一の標準毒IDのみをサポート。
- `ToxinProfile`: 毒ごとの閾値、排出、損傷特性。初期は旧`ToxinSettings`と1対1に対応。
- `ToxinBurden`: 生物個体が保有する毒種別の体内量。生物の種類に依存しない値オブジェクト。
- `ToxinResistance`: 毒種別の遺伝的耐性。毒の生成能力とは別の遺伝形質。
- `ToxinPhysiology`: 排出・損傷・防御量を計算する副作用のない関数。資源台帳やHPへの反映は呼出側。
- `ToxinProduction`: 生物個体ごとの毒生成形質と生成コスト。07.3ではインターフェースを設計し、個体差は07.4で導入。
- 植物・草食・肉食の行動（生成、食事、攻撃、捕食、死体摂取）は生物種固有のまま。毒の生理計算とデータ表現だけを共通化。
- 07.3の共通化は**機能を有効化することとは別**。肉食への毒効果、無毒植物、複数毒は後続フェーズで別々に有効化する。
- 設計は暫定案。07.3.2で実コードに合わせて命名・データ型を最終決定する。固定長配列と可変長コンテナの性能は100万体目標に照らして評価する。

## 回帰比較契約
- 旧版（本ZIP）と新実装を、同一seed、同一JSON、同一Tick数、同一自然発芽パラメータで比較。
- 基準設定: `config/standard-toxin.json`（通常毒、損傷係数0.010）、毒OFF、耐性OFF、必要なら毒ON耐性OFF。過去のx10名称は履歴のため保持。
- 指標: 生物種別個体数、出生死亡、平均耐性、毒摂取量、排出量、HP損傷、耐性による軽減、植物生成費、耐性維持費、総栄養/総エネルギー収支、診断エラー。
- 07.3.2の初回抽出では**同一seedでTickごとの完全一致を第一目標**とする。浮動小数の計算順変更で差が出た場合、無条件に許容せず原因・誤差上限を記録して承認を得る。
- 既存の140ランは統計的な参考値。旧版と新版の回帰比較には同一条件での再実行が必要。過去のx10結果を単純に新実装の再現性証明とはしない。
- 現在のWeb標準毒は`SimulationConfig::default()`と一致しない。Webとバッチの完全同条件比較にはseed/自然発芽/初期個体数を揃える必要がある。
