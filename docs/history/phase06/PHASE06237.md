# フェーズ06.2.37 — バッチ検証とWeb観察の運用統一

## 運用ルール（今後の標準）

1. **Rustテスト**: `cargo test --workspace` で変更の回帰を確認する。
2. **短時間のバッチ検証**: PowerShellで1,000 Tick程度を実行し、CSVの列・行数・終了Tickを確認する。
3. **正式な定量評価**: PowerShellの `run_phase06237.ps1` を使用し、同一条件で **50,000 Tick × 5シード（12345～12349）× 3条件** を実行する。必要に応じシード数を増やす。
4. **Web版**: 行動・描画・不自然な動きの観察に使う。気になる動作があった場合にCSVと状況を共有する。Web版だけで統計的優劣を判断しない。
5. **解析**: `analyze_phase06237.py` で生存・絶滅Tick・捕食・繁殖・遺伝子分布・保存則誤差を比較する。異常値があれば該当シードのログを調べる。
6. **再現性**: 実行した設定JSONとCSVを条件・シード別に保存し、設定を変更した場合は別の条件名で管理する。

## フェーズ06.2.37で実装した変更

- 従来の `carnivore_verification` CSV末尾に `carnivore_ambush_gene_mean` と `carnivore_ambush_gene_variance` を追加。Web版と同じRustの `behavior_genetics_snapshot()` を使用する。
- 肉食動物が絶滅した行では平均・分散が0になる。**遺伝子の変化を評価するときは `carnivores > 0` の行だけを使用**する。
- 従来型（`movement_strategy=0`）、待ち伏せ型（`1`）、遺伝型（`4`）を同一シードで比較する。設定は `config/phase06237-*.json` に固定する。
- Rustの生態系ルール、遺伝・突然変異・移動の挙動は変更しない。今回の目的は観測と比較の統一。
- 学習・突然変異イベント数の計測、親子系譜の追跡は未実装。

## 実行方法（プロジェクトルート）

```powershell
cargo test --workspace

.\run_phase06237.ps1 -Ticks 1000 -SeedCount 1

.\run_phase06237.ps1

python .\analyze_phase06237.py

```

結果は `results/phase06237/{fixed,ambush,genetic}/` に保存する。過去の `run_phase06231.ps1` は当時の実験再現用として残す。

## 検証時の注意

- 条件間比較ではシード・Tick・サンプリング間隔を揃える。
- 遺伝子の平均値だけで進化・適応を証明したと判断しない。選択圧・出生・死亡・遺伝の追跡は今後の課題。
- `strategy_ambush_rest_ticks` などの既存カウンターは遺伝型（4）の行動を必ずしも網羅しない。行動選択の完全な計測は別途実装が必要。
