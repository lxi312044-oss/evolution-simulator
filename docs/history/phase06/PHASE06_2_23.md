# フェーズ06.2.23 — 植物回復後の草食動物の再増殖

## 目的
植物が増加した後（特に8,000 Tick以降）、草食動物が摂食から得たE/Nを蓄積して自然繁殖できるかを検証する。

## 比較条件（繁殖閾値はすべて06.2.22 controlに固定）
| モード | 変更 |
| --- | --- |
| control | 変更なし |
| digestion-150 | 胃内N消化速度 0.05→0.075 N/Tick |
| energy-efficiency-90 | 摂食E取得効率 0.80→0.90 |
| feeding-120 | 摂食N上限 0.35→0.42 N/Tick |
| combined | 消化速度1.5倍＋摂食E取得効率0.90 |

注意: これらは**比較実験用の仮説**であり、改善を保証する調整ではない。摂食Eは植物から移転し、獲得できないEは熱へ移るため、Eは創出しない。胃内Nは既存のN口座間で移転する。

## 実行
```powershell
cargo test --workspace
powershell.exe -NoProfile -ExecutionPolicy Bypass -File ".\run_phase06223.ps1" -Ticks 1000 -SeedCount 1
powershell.exe -NoProfile -ExecutionPolicy Bypass -File ".\run_phase06223.ps1"
python .\analyze_phase06223.py
```

5条件×5シード×50,000 Tick。`results/phase06223/summary.csv` と `results/phase06223/phase06223_period_analysis.csv` を比較。

## 判定基準
- 8,000 Tick以降の出生数と最終生存シード数が基準より増えること
- 4,000～8,000 Tickの飢餓HP損失と植物急減が悪化しないこと
- 肉食動物の出生・絶滅Tickを悪化させないこと
- nutrient_error, energy_error が許容誤差内に収まること
- 人工的な再導入・個体数固定は行わない

## 留意点
フェーズ06.2.23は実験条件を追加したもの。Rustの摂食・消化ロジックは既存設定値を参照するため、コード変更は不要。実行前に `cargo test --workspace` を行うこと。Web画面の選択肢は従来のままで、今回の5条件はバッチで検証する。
